# Decisions

_Key decisions, the options considered, and the reasoning behind each._

## Design-phase decisions (2026-10-17)

| # | Decision | Options considered | Reasoning |
|---|---|---|---|
| DS1 | **Shared request/response and entity types are plain TypeScript types. No schema library (Zod etc.).** The API checks required fields by hand; channel config is checked only by that channel's `validate()`. | Plain TS types · Zod in `packages/shared` · Zod in the API only | Matches CLAUDE.md and the plan-v2 cut ("General API input validation → reduced"). It adds no dependency, and at this scale Zod would save almost no time. Zod in the API only would mean keeping two type definitions in sync. |
| DS2 | **Names: `ChannelConnection`, `Source`, `NotificationChannel`.** The Phase 3 prompt's `Destination` and `EventSource` are not used. | Keep the doc names · Rename to the prompt's names · Rename `Source` only | CLAUDE.md, A13 and plan-v2 S1–S3 already use these names. Renaming would touch several docs and make nothing clearer. |
| DS3 | **The design phase produces `docs/design.md` only.** Shared types are written in S0/S1 and `apps/api/src/db/schema.sql` in S1, following plan-v2. | design.md only · A minimal `packages/shared` + schema.sql now · Build S0 first | S0 isn't scaffolded yet, so code written now couldn't be typechecked. This keeps the slice order. |
| DS4 | **Connection delete blocked while in use** (D6, closes A13). `DELETE /me/connections/:id` returns 409 with the alerts using it. `alert_connections.connection_id` is `ON DELETE RESTRICT`. | Cascade + warning · Block delete · Cascade + auto-pause | Developer's choice: alerts never quietly lose a target. Cost: the 409 error UI on the connections page (~0.15h in S3, taken from the buffer). |
| DS5 | **Delivery rows survive deletes.** `deliveries.alert_id` and `connection_id` are nullable with `ON DELETE SET NULL`. Each row stores snapshots taken at send time: `user_id`, `alert_name`, `connection_label`, `channel_type`. `user_id` is needed so `GET /me/deliveries` still works after the alert is gone. | SET NULL + snapshot · Cascade delete · Soft delete | History (A17) and the admin log (A9) stay complete without the query filters soft delete needs. UNIQUE(alert_id, event_id, connection_id) still dedupes live rows. SQLite treats NULLs as distinct, but a deleted alert never sends again. |
| DS6 | **`GET /api/users` is public** (mounted before the auth middleware). It returns only `{ id, name, role }` for the mock switcher. Every other endpoint still needs `X-User-Id`. | Public endpoint · Seed IDs hard-coded in the web · Default user header | The switcher has to list users before an identity exists. Mock-only, and removed when real auth comes in (A8). |
| DS7 | **`GET /api/previews/:id` is public, and the ID is a random UUID** (`crypto.randomUUID()`). This is the email preview link (A10). | Unguessable public ID · Fetch + blob URL · `?userId=` query param | A plain link opened in a new tab carries no header. "Anyone with the link" is acceptable locally and listed as a known limit. A `userId` query param would break the rule against trusting identity from the URL. |
| DS8 | **"Send test" is logged as a delivery.** `deliveries.kind` is `'alert' \| 'test'`. Test rows have `alert_id` and `event_id` NULL and show in the user's history and the admin log, labelled "Test". The endpoint still returns the `SendResult` for inline UI feedback. Because NULLs are distinct in the UNIQUE key, repeated tests are never deduped, which is intended. | Return the result only · Log as a test delivery · Separate `test_sends` table | Developer's choice: test sends are visible in the same log the admin monitors (A9, A16). Cost: the `deliveries` table moves into S1, and delivery queries and the history UI must handle `kind` (~0.15h, taken from the buffer). |
| DS9 | **(revised 2026-10-18, F6)** **BBC `sourceEventId` is the `<guid>` without its `#n` suffix** (the article URL part). Was "the full `<guid>`, including the `#n` suffix". The F6 check (testing.md S2-12) found that the suffix changes when a story is updated: 3 of 22 articles went from `#0` to `#1` with the same `pubDate`, so the full guid would store and send the same story again. Like USGS revisions (DS11), an updated story is not sent again. | Strip the `#n` suffix · Keep the full guid and document re-sends as a known limit | Developer's choice (strip). Keeps A7 ("never send twice"); the change sits only in the BBC adapter's normalise step, as planned. Side effect: BBC events stored before the fix keep their `#n` id, so each is inserted once more under the new id; events older than `enabled_at` are not matched (D7), so only a story published after it could be sent one more time. |
| DS10 | **USGS severity bands:** `mag < 4.5` → `low`, `4.5 ≤ mag < 6` → `medium`, `mag ≥ 6` → `high`. Feed: `summary/2.5_day.geojson`. | <4.5 / <6 / ≥6 · <4 / <5.5 / ≥5.5 · the 4.5 feed with higher bands | 4.5 is USGS's own "significant worldwide" feed cut-off, and M6+ is where strong damage typically starts, so the edges follow known conventions. Closes the "band edges" point left open in A1. |
| DS11 | **USGS revisions are ignored (known limit).** USGS updates a quake's magnitude and details after first publishing it (`properties.updated`). Events are deduped on (`sourceId`, `sourceEventId` = `feature.id`), so only the first version is stored and matched. A later upgrade (e.g. M5.8 → M6.1) does not trigger a new or higher-severity alert. | Accept and document · Upsert on `updated` and re-match | Re-matching revisions would mean deliveries per event version, which goes against "never send twice" (A7). Documented as a known limit in the README. |
| DS12 | **Ownership of IDs in a request body is checked in the API.** Every `connectionId` in `AlertInput` must belong to `req.user`; otherwise `POST`/`PUT /me/alerts` returns 400 `fieldErrors.connectionIds`, with the same message for an unknown ID and another user's ID. A connection's `type` is immutable: `PUT /me/connections/:id` with a different `type` returns 400. Closes design review C1. | API check only · API check + composite FK (`user_id` on `alert_connections`) · 404 instead of 400 | Developer's choice. The schema can't tie an alert's owner to its connections' owner, so without the check user A could link B's connection: A's alerts would send to B's targets, B could never delete it (DS4's 409), and the 409 would show B the names of A's alerts. One API helper matches how every other ownership check works and costs ~0.05h; a composite FK would still need the check to return a 400. 400 rather than 404 because the URL resource exists; the body is what's invalid. |

| # | Decision | Options considered | Reasoning |

| S0-2 | **Node floor raised (revises D2):** `engines.node` = `^22.22.3 \|\| >=24.15.0`, `.nvmrc` = `24`. Was "≥ 22.13". | Raise the floor · Older Angular · Node 24 only | Angular 22.2.3 requires `^22.22.3 \|\| ^24.15.0 \|\| >=26`. `node:sqlite` is still built in on both lines, so D2 is unchanged in substance. |
| S0-3 | **Angular 22.2.x conventions:** standalone components, OnPush, signal APIs (`input/output/model/computed/signal`), built-in control flow, `inject()`, functional guards and interceptors, lazy `loadComponent`, typed `nonNullable` forms. Stable APIs only. `skipTests` and `changeDetection: OnPush` are set in the schematics; `strictTemplates` is on. | — | Follows CLAUDE.md "Modern Angular". | S0-4 | **Test runners: Vitest for both.** Web uses `@angular/build:unit-test` (Vitest + jsdom, no browser); the API uses Vitest. Root `npm test` runs every workspace test script and fails if any fails (D4). | Vitest both · Vitest web + `node:test` api | One runner and one assertion style. | S0-5 | **Lint and format: ESLint (typescript-eslint, angular-eslint) + Prettier**, root `npm run lint`. One flat config at the root (`eslint.config.js`) covers all workspaces; `no-explicit-any`, `ban-ts-comment` and `no-non-null-assertion` are errors. No `ng lint` target. | Root config · Per-workspace configs | Decided 2026-10-17; not in plan-v2. One config and one command are simpler; `ng add angular-eslint` created a web-only config, which was moved to the root. |
| S0-6 | **`SEVERITIES` crosses the wire through `/health`:** `GET /api/health` → `HealthResponse { status: 'ok'; severities: readonly Severity[] }`. | Add to /health · New `/meta` · Temporary | Proves the shared runtime import end to end without a new endpoint. The design.md §4 row is updated to match. |
| S0-7 | **`node:sqlite` warning:** none on Node 24.22.0 (`require('node:sqlite')` loads with no ExperimentalWarning; SQLite 3.53.4). Node 22.22.x was not tested. | — | Recorded from testing.md S0-5; nothing to suppress or document for Node 24 users. |

### Answers D1–D5 and planned cuts
D1–D5 are recorded in assumptions.md ("Answers to open questions"). Their technical effects: D1 → news severity is set only in the news adapter's normalise step; D2 → `node:sqlite` (floor revised by S0-2); D3 → no cooldown (Stretch); D4 → the local `npm test` gate is the only CI; D5 → 9h plan, 1h buffer. The planned cuts are the plan-v2 table "Moved to Stretch / Out of scope": cooldown, Ethereal, retry, reduced `.http` coverage, reduced API validation, no repository round-trip tests, no GitHub Actions.

## S1 decisions (2026-10-17)

| # | Decision | Options considered | Reasoning |
|---|---|---|---|
| S1-1 | **`schema.sql` holds every table from design.md §1 from S1 on**, as table definitions only. No S2/S3 logic is built early. | All tables now · S1 tables only, rebuild `deliveries` in S3 · S1 tables only, FK columns without constraints | Developer's choice. `deliveries` is needed in S1 (DS8) and has FKs to `alerts` and `events`; SQLite cannot add an FK to an existing table, so creating everything once avoids a table rebuild later. |
| S1-2 | **Email previews live in an `email_previews` table** (`id` UUID, `subject`, `html`, `created_at`); `deliveries.preview_id` points to it. A preview is stored on **every** email send, also when SMTP is configured. | `email_previews` table · In-memory map · `html` column on `deliveries` | Developer's choice. Preview links in history keep working after an API restart, and the log table stays free of message content. Fills a gap in design.md §1 (no table for the preview itself). |
| S1-3 | **Slack `webhookUrl` is optional.** Empty → the send is a `dry-run`. When filled in, it must start with `https://hooks.slack.com/` (checked in `validate()`). | Optional + Slack-host check · Optional, any https URL · Required + `SLACK_DRY_RUN` env flag | Developer's choice. Makes A11's "no URL → dry run" reachable, and the host check stops the server from POSTing to arbitrary URLs a user types in. |
| S1-4 | **Small defaults:** the chosen mock user is remembered in `localStorage` (first load picks the first non-admin user); the DB file is `apps/api/data/alerts.db` (gitignored by `*.db`), overridable with `DB_PATH`, and tests use `:memory:`; the connections list masks a Slack webhook URL, which is shown in full only in the edit form. | — | Accepted by the developer as proposed. |
| S1-5 | **`nodemailer` added** to the API for A10's optional SMTP transport. | nodemailer · Hand-written SMTP | The standard Node SMTP client; writing SMTP by hand is not worth the time. |

| S1-6 | **The admin channel switch blocks new use, not existing data.** For a disabled channel type: POST of a new connection → 400; **Send test** → `{ status: 'failed', error: 'Channel disabled by admin.' }`, nothing sent and no delivery row; **PUT still works** (the type only has to be registered), so existing connections stay editable. | Send test respects the switch, PUT allowed · Send test bypasses the switch (document only) | Developer's choice after the S1 review (m3). Matches DoD 6 ("Disabling … a channel takes effect") for every path that sends; renaming a connection sends nothing. |
| S1-7 | **Web `typecheck` runs `ngc -p tsconfig.app.json --noEmit`** (then `tsc` for the specs), so templates are type-checked by the gate. | `ngc` · `tsc` + rely on `ng build` | Developer's choice after the S1 review (M3, first raised as S0 review M1). `tsc` alone let a template typo pass all three gates. `ngc` comes with `@angular/compiler-cli`, already installed. |

## S3 decisions (2026-10-18)

| # | Decision | Options considered | Reasoning |
|---|---|---|---|
| S3-1 | **Simulating an existing `sourceEventId` re-dispatches the stored event.** The UNIQUE key keeps the first event; it goes through the dispatcher again, and the delivery dedupe (A7) stops any resend, so the response has `deliveries: []`. | Re-dispatch the stored event · Return it without dispatching | Developer's choice. The plan-v2 S3 check "simulate again → no new delivery" then tests the delivery-level "never send twice" rule, not only event dedupe. Side effect: an alert created between the two simulations does get the event. |
| S3-2 | **(revised 2026-10-18, S3 review M2)** **A simulated event must use the source's `fixedSeverity` when it has one** (400 `fieldErrors.severity`, e.g. "Items from BBC World News are always medium."); a source without one takes any severity. Was "any severity, for every source". | Reject (400) · Override silently · Any severity, with D1 and CLAUDE.md carrying the exception | Developer's choice (reject). Any severity broke D1 and the CLAUDE.md "fixed medium" rule, and made the alert form's "will never match" hint false. The route reads only the generic `fixedSeverity` (S3-3), so no source-specific code moves outside the adapter. |
| S3-3 | **`Source.fixedSeverity?: Severity`**, set only by the BBC adapter and passed through `SourceSummary`. The alert form shows "items from this source are always …" when it is present. | `fixedSeverity` on the source · The web checks `sourceId === 'bbc'` | Developer's choice. The web knows no specific source; when "Smarter news severity" (Stretch) lands, only the adapter changes. |
| S3-4 | **An alert needs at least one connection** (400 `fieldErrors.connectionIds`). | At least one · Zero allowed | Developer's choice. An alert without a connection can never notify anyone; matches D6 (alerts never lose their targets). |
| S3-5 | **Small defaults:** `GET /sources` lists every source with `enabled`, and a disabled one can still be chosen (labelled "disabled by admin"); an omitted `sourceEventId` becomes `sim-<uuid>`; sends within one dispatch run in parallel; the home route is `/alerts`. The poller gets an `onNewEvents` callback and stays unaware of channels; a dispatch error is logged and does not mark the source failed. | — | Accepted by the developer as proposed. |
| S3-6 | **The dev server does not prebundle `@alerts/shared`:** `apps/web/angular.json` serve options `"prebundle": { "exclude": ["@alerts/shared"] }`. | Exclude from prebundling · Explicit `.ts` extensions in the shared re-exports · One shared `index.ts` file | Developer's choice. With prebundling on, the dev server treats every package import as external and hands it to Vite's optimizer, which resolves only `.mjs/.js/.cjs`, so the extensionless re-exports added in S1 (`export * from './identity'`) failed once the prebundle cache was rebuilt. Excluded, the shared sources go through Angular's own compiler, as they already do in `ng build` and `ng test`. One line of config, no code change. |
